When things fail

Alpha 1.0 protects against the loss of one node, on any cluster size. It keeps working degraded, repairs when the node returns, and refuses to guess when it cannot be sure. It does not survive a second loss, and it does not yet repair onto a different node.

The recovery picture

  1. Detect. The client marks a peer down after four consecutive failures and probes it about once a second. Servers track members the same way; a returning node gets a new incarnation.
  2. Keep serving. Reads decode from two fragments; writes carry on degraded; metadata uses the surviving voters.
  3. Remember. Every degraded stripe or segment is marked on its metadata group, so the debt is visible and counted.
  4. Return. The group leader audits the returned member, rebuilds the fragments it missed, verifies each by reading it back, and only then clears the mark.
  5. Close. Protection: full. Until then a second loss would be fatal for those stripes.

What alpha 1.0 does not claim

  • No protection against a second node loss on any cluster size. Four nodes are not 2+2.
  • No automatic repair to another node, no online node removal, no rebalancing.
  • No sudden-power-loss qualification, and no indication of degraded state on the mount itself, only in status and the client log.
