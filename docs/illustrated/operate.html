Operating a cluster

Configuration is the command line. There is no config file, node id or member count. Four programs and two wrapper scripts make up the whole alpha surface.

efsd

Storage and metadata daemon. efsd ADDR:PORT STORAGE creates a cluster or restarts the node; --join [SEED] joins one. One to 24 storage roots, --quota, --meta-storage.

efs-fuse

The Linux client. efs-fuse NODE:PORT MOUNTPOINT; one address is enough. --stop drains and unmounts.

efs-mgmt

Status, settings, policies, diagnostics. Mostly read-only; a few commands change policy or ask a member to act.

server.sh, client.sh

Wrappers with logs, PID files and orderly-stop checks. Stop clients first, then servers.

Starting and stopping

  1. Start servers. ./scripts/server.sh 10.0.0.11:17432 /data/efs on the first host; the same with a seed address on two joiners. The cluster forms at the third member.
  2. Check. ./efs-mgmt status 10.0.0.11:17432 exits 0 only when every member is up.
  3. Mount. ./scripts/client.sh 10.0.0.11:17432 /mnt/efs returns once stat works.
  4. Unmount. ./scripts/client.sh stop /mnt/efs refuses while a process uses the mount, drains writes, revokes the session. See Sessions.
  5. Stop servers. ./scripts/server.sh stop /data/efs on each host. A daemon stops on SIGTERM within 55 s and writes an exit record.
server.sh stop exitsMeaning
0Orderly: fragment syncs, reclaim journal and usage flushed.
3Forced exit; stores preserved, the next start runs verified recovery.
4A barrier failed or the outcome is unknown; stores preserved, rerun to start on them.

Reading efs-mgmt status

Pick a situation, then click a line to see what it tells you. The numbers here are made up; the section names and their order follow the alpha guide.

Effective settings

efs-mgmt settings NODE:PORT lists what a daemon is actually running with; efs-mgmt settings --mount MOUNTPOINT does the same for a client, on the host that mounted it. Read-only. One line per setting, tab separated:

namevaluedefaultprovenancekind
the settingwhat is in forcethe built-in defaultbuilt-in, environment, command line, automatic or policydeployment input, numeric tunable, policy, transport or build
  • Covered: the 9 deployment inputs, the numeric tunables, the cluster .efs and expiry policies with their versions, the durability window, the transport and the build.
  • Left out and only counted in the header: observability switches (34) and fault or test hooks (62).
  • One reply of at most 8 KiB. The command exits non-zero if the node refuses, cannot be reached or the reply is truncated.

.efs directory commands

On a mount, every directory has a lookup-only .efs/ folder with ls and find that query the cluster directly instead of walking the tree through the kernel. They need Python 3 on the client, and they work only while the cluster commands-policy allows them (on by default; efs-mgmt commands-policy NODE:PORT get). Build a command:
