The cluster

A cluster is three to sixteen storage nodes on separate hosts. Every node stores data. Exactly three nodes vote for each of the two metadata groups, so adding nodes adds capacity and spreads work but not protection.

    Usable capacity

    equal nodes

    Every chunk stores 1.5 bytes of fragment per byte of data (two data plus one parity fragment), so usable space is about two thirds of the summed quotas. df and efs-mgmt status report this logical figure, not raw disk space, but differ when a member is unreachable: df retains its last known figures, while status reports degraded capacity and the up count. Node loss alone does not reduce df; it is not an availability guarantee. Unequal quotas are bounded by the three-node placement rule and need the exact calculation in status.

    Rules worth knowing

    • Same build everywhere. A peer or client with a different build identity is refused at connection, so upgrades stop everything, replace binaries and start again.
    • Storage roots are fixed when a node's store is created (one to 24 directories). To add capacity, add a node.
    • No rebalancing. New writes use a new node at once; existing data stays where it is.
    • No online removal and no automatic re-homing of a lost node's data in alpha 1.0.
