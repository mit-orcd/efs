How EFS works, in pictures

EFS is a file system that spreads your files over several servers, so one server can fail and nothing is lost. You mount it like any folder on Linux. These pages show how, and most of them let you break a server and watch what happens.

Words you will meet

Node
One storage server running efsd. A cluster has 3 to 16.
Chunk
A 128 KiB slice of a file, the unit that is protected.
Fragment
A 64 KiB piece of a chunk kept on one node. Two data fragments (D1, D2) and one parity fragment (P).
Parity
P is D1 XOR D2. Any two of the three rebuild the third.
Degraded
Stored or running with one piece missing. Still correct, but a second loss would hurt.
Metadata
Everything about files except their bytes: names, sizes, permissions, where fragments are.
Shard
A slice of the metadata. In alpha 1.0 the shards belong to two groups.
Raft, voter, leader
The agreement protocol. Each group has three voters; one is leader; a change counts when two of three have it.
Publish
The metadata commit that makes written data visible. Other clients do not see the write before it.
Session, fence
A mount's identity. Fencing cuts off an old session safely before its locks are released.
Reclaim
Background deletion of fragments nothing refers to any more.

How to read the pictures

  • Blue is data, amber is parity, violet is the second metadata group, a dashed red outline is a node that is down.
  • Sizes are real where the code fixes them: a chunk is 128 KiB, a fragment 64 KiB, at most 16 nodes, two metadata groups of three voters.
  • Which node holds which fragment in the diagrams is illustrative. The product places fragments by a hash of the file and chunk, and records the result in the chunk map.
