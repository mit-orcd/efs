## What changed

| area | change |
| --- | --- |
| Raft host | removed the eager `TRUNCATE` apply and packing, `LANE_FENCE` (apply, packing, cross-group drain), the in-entry tail CAS, and the `EFS_D25_LAZY_TRUNCATE` switch; SETATTR SIZE always runs `host_truncate_lazy`; a `TRUNCATE` that is not exactly 86 B answers PROTO; tag 20 (retired `LANE_FENCE`) is refused, never skipped |
| metadata | removed `efs_meta_apply_truncate`, `efs_meta_apply_lane_fence`, the range-delete scanner, the tail publish, `struct efs_meta_truncate` and their capacity constants (about 1,000 lines) |
| client | no tail rewrite before SETATTR; after a shrink the local map, read cache and clean dirty-cache images are dropped from chunk `size / cs` (the boundary chunk is pulled again, now masked) |
| simulator | `efs_sim_truncate(sim, client, ino, size)` proposes the logical entry (classified like the host; the log index is the opid sequence); the sim models no sweep, so masked rows stay |
| tests | eager tests converted to the logical entry plus a driven sweep: range delete and present count, append cursor, lane-local publish, BOOTSTRAP floor, bounded multi-sweep lane (1,000 rows), GC records per base and delta (W62), boundary clip keeps the fragment set live, prepared-intent exclusion, failed batch; tests of the removed paths (oversized eager truncate, `LANE_FENCE` paging and lane history, tail stubs) dropped; `test_truncate_prefix` rewritten for the no-rewrite client |
| docs | architecture §7.3 (single-entry truncate, inode as the single history authority, lazy adoption, clip sweep and retirement), I22, op matrix and glossary; D25 contract row; decisions register |

## Limits and remaining gates

- orcd-mini (the shared development cluster) and RDMA are not run; W43
  closes with those.
- The step-4 limits stand: the sweep scheduler needs a node hosting both
  groups; throughput is bounded by 64 proposals per GC pass and 64 changed
  rows per entry (2 GiB drained in about 10 s), not measured above 2 GiB.
- The simulator does not model the sweep; sweep behaviour is covered by
  `test_meta_apply` and the cluster gates.
- The typed lane-history admission path is still in tree, tested and
  served (`EFS_MSG_LANE_WRITER_VIEW`, the lane bootstrap capture in
  `raft_host.c`); with `LANE_FENCE` gone nothing in production appends to a
  lane's own history any more. Retiring that path or rebasing it on the
  inode history is a follow-up, not part of this step.
- One run per configuration; TCP only.
