The reverted fan-out trial uses at most three temporary workers plus the GC thread. Workers
join before their stack jobs expire, before another inode and before host
shutdown. Thread-creation failure executes synchronously. Missing or failed
members retain the reap ledger. The production-helper regression covers these
verdict, fallback and lifetime conditions.

The W84 prepared/committed barrier is compiled only with `EFS_FAULTS=1`.

its PID/stage before the harness kills that coordinator. Normal binaries have
no barrier behavior.

## D26 result and next design

The settled serial run spends11617ms in fencing,2254ms in lane sweeps and
1105ms in REAP_DONE; the candidate spends8285/2402/1414ms. These are sums
over recorded passes, including cleanup generated by metadata probes. They
do not prove a universal speedup. Metadata still alternates between about
3ms create/7ms append and47–51ms create/60–64ms append. No worker-thread
optimization is activated. Per-pass attribution is retained in normal code.

A useful next D26 phase is bounded batching of dead-inode fences/cleanup,
with per-inode verdicts, all-member acknowledgement and the durable retry
ledger preserved. Fsync removal, age-only deletion and acknowledging a
partially cleaned inode are not acceptable remedies. Define versioned
request bounds, partial-result replay and older-node fallback before coding
that protocol; D26(ii) remains a design choice.

## Replacement read correctness

The initial durable-COMMIT crash run failed with cold ENOENT. An isolated
copy of the stores reproduced a lookup that returned the old dentry (inode2074)
while its inode lookup already returned NOT_FOUND; a second later the name
resolved to the new inode36. Original stores were preserved. The FUSE callback
also mapped almost every RPC failure to ENOENT. Both defects are repaired:
FUSE preserves authority/resource errors, and server LOOKUP returns BUSY when
a captured dentry's inode disappears, including the forwarded GETATTR path.
It does not turn actual absent names into BUSY. Production-function regressions
cover both paths, true absence, authority failures and successful adoption.

The repaired full coordinator-fault/physical-GC/restart fixture passes. The
rename syscall may report EIO/EBUSY after coordinator death even when COMMIT
was durable; the acceptance test verifies authoritative resulting state rather
than treating the lost reply as proof of rollback. Both original failure runs
and the cloned-store observations are retained alongside the passing run.
