## ior hard EIO (W161)

At 14:18 one rank's `write()` returned EIO at offset 554,694,400 and ior
aborted on its `rc >= 0` assertion. The node9901 client log for the shared
file (inode 4642):

- 14:17:36 n1: `report-split … stale=1 … rc=-14` (STALE) for one REPORT.
- 14:17:42 client: `report-resolve … rc=-13 … outcome not known; same-identity
  lookup`, then `outcome=partial rc=-14 first_rc=-13`;
  `background-pressure ino=4642 rc=-14 retained`.
- 14:17:50–14:18:33: the retained error repeats; `fsync` and `flush-meta`
  return stale generation (-14) and once BUSY (-13), until the file is
  removed. The cluster stayed OK (3 up) and later runs were clean.

The REPORT's outcome was resolved as partial and the stale-generation error
was kept and surfaced to the application instead of being replayed. Cause not
established; candidates are W155's bounded same-identity resolution and K32's
batched publication of a REPORT's units. One failure in four runs; not
reproduced in three reruns.
