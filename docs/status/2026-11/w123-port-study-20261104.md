# W123 recovery branch: what is proven and portable to devel (Nov 4, 2026)

Coordinator study of `devel-w123-recovery` (head `90fc6f34b`, Nov 3) against
devel `15f346b48` (wave 54). Question from the user: which differences on the
branch are proven improvements that should be ported, independent of whether
the W123 crash-recovery feature itself ever merges. Method: `git diff
--numstat devel...devel-w123-recovery`, `git log` of the 180 commits touching
`src/` or `include/`, `git cherry` and `git merge-base --is-ancestor` against
devel, `git apply --check` of each candidate's source hunks on devel, and the
branch's own evidence pages (`w123-wait-diagnostic-20261031.md`,
`w123-checkpoint-origin-pair-20261026.md`, `w123-devel-integration-20261028.md`,
`w123-amd-handoff-20261023.md`, all on the branch only). No code was changed
and nothing was run on a cluster for this page.

## The feature itself: not portable, not accepted

The recovery feature (`src/recovery/`, `recovery_runtime.c`, the `raft_host.c`,
`store.c` and `meta_apply.c` hooks, the 143 live tests, the 138 pages) passed
all 121 correctness receipts on every source since `31aeadb0e` (Oct 31) and
failed the formal throughput gate on every one of them: −15.2 % to −17.5 %
against a −10 % limit at `31aeadb0e`, `e4d7fd485`, `5ae9cb9a0`, `020a4fd8f`,
`651e4ba39` and `c66f4949a` (Nov 3). The latency gates (fsync p95, visibility
p95, both ≤ +20 %) have passed since `020a4fd8f`. The branch has been chasing
the throughput cost since Oct 18 without a converging cause; the Nov 3 state is
"current phase analysis started". This page takes no position on the feature.
Whatever the user decides, the branch's `results/` tree (176 k lines of raw
captures) should not reach devel: raw data stays outside Git with a location
and hash.

## Portable candidates, ranked by proof

"Applies" means `git show <sha> -- src include tests/*.c tests/*.py | git apply
--check` passes on devel today; Makefile and budget wiring is by hand in every
case. Proof classes: **A** deterministic defect with a reproducing test, **B**
measured component gain with identical output, **C** correct by inspection with
a unit test and no measurement, **D** plausible, and unqualified by the branch's
own words.

### A. `020a4fd8f` raft: notify late followers of an already committed prefix

`src/raft/raft.c` +9, `tests/test_raft.c` +21/−3. A priority commit probe can
overtake a delayed data batch and proves only the follower's old
`match_index`; when another peer establishes quorum and the delayed batch then
acknowledges, `on_ae_rep` sees no new leader commit and sends nothing if no
entries queue, so the follower waits a heartbeat. The fix sends one commit
probe when a successful reply advances that peer's match index across a
committed prefix it has not been told about; a probe reply without match
progress cannot re-trigger it. Proof: the expanded test checks apply before any
tick, fails on the old code with exactly two assertions (exit 1), passes native
and ASan/UBSan/leak-check on fcstor003 and native on the Mac, under both ACK
window policies. On the branch's six-arm formals the fsync p95 went from
+1,397 %/+1,179 % to +15 %/+16 % and visibility p95 from +605 %/+567 % to
−6 %/+8 % between the `5ae9cb9a0` and `020a4fd8f` campaigns; the branch calls that a cross-campaign
observation, not a controlled effect, and this page agrees. Devel: no
equivalent; `on_ae_rep` returns `EFS_OK` at that point. Applies cleanly.
**Port.**

### B. `2f5e8ae69` CRC32 slicing by eight

`src/common/checksum.c` +24/−6, new `tests/test_crc32.c` (82 lines, checks the
sliced result against the byte table and carries `--bench`). Same IEEE
polynomial, initial and final XOR, no hardware CRC32C. Proof: component bench
591.2 MiB/s byte table against 3,408.4 MiB/s sliced on 128 MiB; a CPU capture
during a W123 diagnostic had CRC32 at 42 of 160 self samples (26 %), mainly
Raft-log and KV-WAL encoding. Correctness PASS native and sanitizers on the
branch's components. Devel: byte table. Applies cleanly. **Port.**

### B. `d78123754` SST writers get owned storage for the 1 MiB stdio buffer

`src/kv/kv_seg.c` +14/−2, new `tests/test_kv_seg_stdio.c` (72 lines). Devel
calls `setvbuf(w->f, NULL, _IOFBF, 1u << 20)` (`kv_seg.c:203`) and its comment
claims one syscall per MiB; glibc ignores the size when the buffer is NULL and
allocates `st_blksize`. Proof: the branch's syscall trace shows SST writes
predominantly 4,096 bytes; the new test asserts 4,096-byte capacity on the old
code (exit 1) and 1,048,576 on the new, and real-SST capacity, readback and
failure paths pass native and sanitizers. No live throughput number. Applies
cleanly. **Port.**

### C. `495f632b4` `kv_sync_dir` returns its error; optional unlink sync deferred

`src/kv/kv_lsm.c`, `kv_compact.c`, `kv_lsm_internal.h`, `tests/test_kv_lsm.c`
+25. Devel's `kv_sync_dir` (`kv_lsm.c:90`) is `void`, opens without
`O_DIRECTORY` and ignores both `open` and `fsync` failure, so a failed MANIFEST
directory barrier is reported as success. The fix returns `EFS_ERR_IO`, retries
`EINTR`, and the two callers fail closed; the sync after unlinking obsolete SSTs
is dropped because the MANIFEST barrier already made the live set authoritative
and resurrected names are discarded as orphans on open. Conflicts in
`kv_compact.c` and the test (about 25 lines to redo). **Port by hand.**

### C. `832a6dcd3` net: compaction yields the reader view across MANIFEST publication

Net effect of `bd98bb005` and its own partial revert in `832a6dcd3`:
`src/kv/kv_compact.c` +9 at the compaction publication (`kv_compact_locked`,
devel line 852): `lsm_view_yield` around `kv_manifest_write`, `lsm_view_reclaim`
after, and on failure close the detached input references without dooming
their files. Devel's flush path already yields there (`kv_compact.c:247-250`);
compaction does not. Proof: a GDB snapshot on the branch shows the Raft pump
owning `h->mu` while waiting for the LSM peek mutex inside
`efs_kv_lsm_apply_room(admit=1)`, with the compactor holding the exclusive
view inside `kv_manifest_write → kv_sync_dir → fsync`; peek waits summed
2.78 thread-seconds in a 15 s capture, maximum 0.32 s on the Raft pump. The
published-counter half (`bd98bb005`) measured −4.1 % and was reverted; do not
port it. The yield alone has a real-I/O regression test on the branch
(`tests/test_kv_compact_manifest_view.c`). Trivial conflict in a header comment.
**Port by hand.**

### C. `8b73e2851` store: retire-ring overflow is BUSY, not a false STALE

`src/server/store.c` +13/−10, `tests/test_ba_upload_retire.c` +57. Devel's
`fragment_retired_since` (`store.c:681-696`, K61 from Oct 30) returns
"retired" when more than `FRAG_RETIRE_RING` (8) retirements hit the bucket
since the PUT's authority read, and both callers turn that into
`EFS_ERR_STALE`: bounded-history uncertainty becomes a false retirement verdict.
The fix returns `EFS_ERR_BUSY` on overflow and STALE only on an exact key match.
Found Nov 3 while the branch chased its own STALE. K38 predates K61 (devel
`5a7463440` on orcd-mini), so this is at most a contributor to the K38 family,
not its cause. Applies cleanly; the port must confirm that devel's client PUT
path takes fresh authority on BUSY rather than retrying with the same mark, and
that the branch test file (which includes `put_fence.c` and `put_upload.c`)
builds on devel. **Handed to Task CV with the K38 logs.**

### D. `84b2ae60c` client: discard a CAS hint a successful STALE repull disproves

`src/client/write.c` +16, `tests/test_stale_recovery.py` +18/−1. The branch
says "whole-workload/performance benefit remains unqualified". Applies cleanly.
**Handed to Task CV.**

### D. `c0df05fce` client: no manufactured REPORT for a committed directory rename

`src/client/ops.c` +10/−7: `efs_client_rename_at` marked the renamed directory
dirty after the server had already committed the rename, so an unrelated fsync
tried to drain a REPORT with no payload (the W123 harness saw `REPORT pending 1
/ inflight 0` refusals). The fix skips the mark for directories, like committed
MKDIR, and never clears an existing mark. Exact-function tests native and
ASan/UBSan on the Mac; the old code fails the ownership assertion. Not
qualified in a full gate by the branch. Source applies cleanly; conflict only in
`tests/test_committed_directory_stage.py`. **Port after CV reports**, since it
touches the REPORT path CV is reading.

### D. `ad8562bf1` + `b0fb1528a` session barriers wait for their exact accepted entry

`src/server/raft_host.c` +38/−13, `apply_wait.h`, `include/efs/meta_cmd.h`,
`include/efs/session_revoke.h` +35, `src/client/inode_rpc.c`. Timed logs on the
branch: an accepted session BEGIN (index 182, term 5) was answered BUSY because
the 400 ms no-progress grant expired during one slow KV flush, and the caller
reproposed it. A delayed duplicate BEGIN after FINISH can fence a new epoch; an
old duplicate ACK can mark its bits. The fix waits the existing 2 s own-entry
hard cap for the exact accepted index and term of BEGIN, ACK, FENCE_LOC and
epoch-bound FINISH without requiring an intervening progress update, never
reproposes them, and gives pre-proposal refusals a distinct receipt (BUSY,
index 0, term 0, salt 9) so clients may repeat exactly those bytes inside the
existing eight-attempt budget. Branch components PASS (506 normal, 0 FAIL; 92
native and 38 sanitizer groups); the branch's three-case diagnostic still
failed strict clean revoke for other reasons. Devel has none of it; devel's K54
and K86 session fixes (`8bd4029f8`, `cdcf16b72`, `a09e8d310`) are separate.
This is a lead for Task CU's unexplained one-off ("returned member stored a
revoked-epoch fragment", 1 in 30) and its two `participant-floor rc=-1`
revokes, not a match. Conflicts in `raft_host.c` and `inode_rpc.c`. **Port as
its own gated task once CU's recurrence question is settled.**

### D. `7b14ff5de` kv: batch up to eight eligible compaction ranges per publication

`src/kv/kv_compact.c` +42/−8, new `tests/test_kv_compact_batch.c`. Correctness
PASS; the branch's own closing note says "do not infer a causal gain from
separate campaign rates", and the formal throughput still failed with it.
Applies cleanly. **Hold** until someone measures it on devel.

### D. `e692f0354` snapshot export write-behind and rotator-thread punch

`src/kv/kv_lsm.c` +46/−30, `src/raft/raft_disk.c` +113/−30, `raft_log.c` +23,
`tests/test_raft_snap_window.py`, `tests/test_kv_lsm.c` cases. Provenance: the
commit message says these were uncommitted edits found in the shared devel
checkout on Oct 17, author session unknown, saved unverified so devel could
move. The motivation is measured: a 0.87 GB export's single fsync stalled Raft
apply for 2.1 s of a 3.9 s export on node9901. Devel has write-behind for the
Raft log (`raft_log.c:584 rot_writeback`) but not for exports, and no
rotator-thread punch. Since Oct 19 the code has been in the branch's `make test`
and passed its 530-test normal suites repeatedly, so "unverified" is stale, but
nothing measured it. Conflicts in both files. **Ask whose work this was**, then
port with a measurement.

### D. `2b9f245b9` store: a retried PUT never rewrites committed bytes

`src/server/store.c` +66/−4, tests in `test_store_overwrite.c`,
`test_store_durability.c`. A W123 prerequisite (a generation names immutable
bytes): a retry of an existing object reads it back and compares; identical
bytes return OK without a second fsync or accounting charge, different bytes
return STALE. Devel's retry rewrites in place. Standalone value is durability
hardening plus skipped fsyncs on duplicates; no measurement. Conflicts in
`store.c` and `test_store_gc.c`. **Defer to the W123 decision.**

## Not to port

- `src/recovery/`, `recovery_runtime.c`, the recovery hooks in `raft_host.c`,
  `store.c`, `meta_apply.c`, `put_ticket.c`: the feature, see above.
- The `diag(w123)` instrumentation (`kv_apply_prof.h`, wait-site observation,
  timeline headers): intrusive diagnostics the branch itself says do not
  qualify performance.
- `results/` (1,293 files), `tests/live/w123-*` (143 files), the 138 pages and
  their Makefile wiring: they belong with the feature, and `results/` breaks the
  evidence-not-raw-data rule wherever it lands.

## What this means for the W171 split

The seven items marked Port, Port by hand or handed to CV decouple entirely
from the W123 merge question: together they are about 150 lines of product
change and all carry tests. After them, the only work still gated on W123 is
the `raft_host.c` and `meta_apply.c` split (W171 phase 2b), because the branch
touches `raft_host.c` on 701 lines and `meta_apply.c` on 392. If the user
shelves W123, phase 2b can start as soon as the stale `agent/*` branches on
those files are deleted; if not, it waits on a throughput fix the branch has
been chasing since Oct 18.
