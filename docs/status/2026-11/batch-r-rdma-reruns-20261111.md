Per operation start, duration and errno are in `k106/ops.jsonl` of each gate directory (82,733, 75,775 and 76,958 operations on TCP).

- TCP run 1: four `fsync` calls started within 2 ms of the stop all returned `EIO` after 7.9993 to 7.9995 s, then the four `close` calls returned `EIO` after 8.0004 to 8.0009 s. The client log of this run was not kept (log collection was added after it).
- TCP run 2: no error, but the client log has `node-waiter-cut: node=1 conns=2 silent for the whole exchange bound` for two requests and, for two others, `inode-rpc: retry type=45 attempt=0 why=recv rc=-6 req_len=332 recv_ms=30000 wait_ms=30013 cut=deadline nid=1` (and `wait_ms=30029`): the in-flight request of type 45 was not cut and waited the whole 30 s. The two `mkdir` of 30.03 s and 30.01 s started at the stop.
- TCP run 3: `fsync` `EIO` after 8.0004 s as the first operation after the stop; four `fsync` and two `close` failed in all.
- RDMA run 1: `inode-rpc: retry type=67 attempt=0 why=recv rc=-13 req_len=844 recv_ms=30001 wait_ms=8004 cut=deadline nid=1` then `report-sync-fail ino=5300221 stage=report total_ms=16001 ... rc=-1` (twice) and two `fsync` `EIO` after 16.0 s; `mkdir` waits of 30.0 s at the stop. ## Deviations from batch D's method

- **Controller on the Mac, not the login node.** `qualify.py` ran on the Mac through [`task_gd_ssh.sh`](../../../scripts/evidence/task-gd/task_gd_ssh.sh): one persistent master per fcstor host, each reached with `-W` through the one shared mux socket (no connection to the login node of its own, no password, `BatchMode`). `fcstor014` was not in the Mac's `known_hosts`; its key and the four others were read from `ssh-keygen -F` in the account's own shared home and placed in a task file used beside the Mac's.
- **libfuse:** batch D's patched copy was gone with its work tree. The same two edits were made again on a fresh copy of `~/w123-deps-20261108-v2/libfuse` (the `fuse3.pc` prefix and the compiled-in `fusermount3` path replaced by a same-length non-existent path, so the setuid system `fusermount3` is used).
- **K42:** the gate list is the one `rdma-4x1b` ran (identity, topology, posix-durability, e1, e2, b6, c5, d1, d3, e4), not the full cell; d4 (NOTRUN in batch D), d5 (TCP only) and the other posix gates are not part of it. Three whole-cell runs replace "run, then two more".
- **K112:** `tests/live/e2_peer_stop_loop.py --runs 20 --port-base 19600 --keep` as batch D, on fcstor012 with all five members on loopback over RDMA (`rdma-k42-e2.cmds`, now [`k112-rdma.cmds`](../../../scripts/evidence/task-gd/h/k112-rdma.cmds)); counts are `grep` over the kept `*.log` files. It does not use `--leaders`.
- **K110:** `tests/live/append_failover.py` starts its own loopback cluster, so these are single-host runs on fcstor012, exactly as batch D's, not distinct hosts. The brief asked for distinct hosts; the harness cannot do it and was not changed.
- **K106:** batch D had no driver for the case (its H15 saw the symptom). [`k106_halt.py`](../../../scripts/evidence/task-gd/k106_halt.py) is new: a `qualify.py` plugin on a driver-owned 3-member cluster (members fcstor012-014, client fcstor010). A run FAILs on any operation error, and on TCP also on any operation of 25 s or more; on RDMA only errors fail. The second mount on fcstor011 is idle.
- **K15:** [`k15_append.py`](../../../scripts/evidence/task-gd/k15_append.py) is new: four writers (two per mount host, fcstor010 and fcstor011, two sessions), one shared file, 4 KiB records, one `O_APPEND` descriptor each, an `fsync` at the end; with `--failover step-down` both groups' leaders are stepped down every 4 s. Verified by reading the file through both mounts. Not covered: the lost-reply mode (needs the fault client build), the kill modes (K110's), a cold remount read and the historical W52 A/B.
- **K43:** the shipped test sets `env['EFS_TRANSPORT'] = 'tcp'`, so it cannot run on RDMA. The RDMA runs use a host-side copy of the test with only that line changed to `os.environ.get('EFS_TRANSPORT','tcp')` ([`k43-rdma-variant.cmds`](../../../scripts/evidence/task-gd/h/k43-rdma-variant.cmds); the copy is deleted after each run, the repo test is unchanged). The cluster is the test's own 6-member loopback cluster.
- **Plugin logs:** the plugin logs of the first K106 run were not collected (added to `k106_halt.py` and `k15_append.py` before the second).
- **One removal:** the first artifact directory was pushed with AppleDouble files and a nested layout; it was removed with `rm -rf` (my own just-created directory, `edelete` was not used) and pushed again.
- Never touched: the live orcd-test cluster, orcd-mini, `/data1`, the `efs` user (a `/tmp/efs` directory on the hosts was left alone), ports 17432-17435, 27432, 27433.

## Reproduction

Prerequisites: the shared mux socket named in [test hosts](../../how-it-works/test-hosts.md), a Mac with `python3`, the five fcstor hosts quiet (`pgrep -u erbmi1 -af 'efsd|efs-fuse'` empty, no listener on 18000-19999).

1. Ship and build: `git archive --format=tar -o efs-gd.tar <commit>`, copy to fcstor012, extract to `~/work/efs-taskGD-fcstor012/src` (and `faults`), recreate the patched libfuse copy, build with the command above.
2. Cells (K42, K106, K15) from the repository root, each on one line: `scripts/evidence/task-gd/run_cell.sh <run> scripts/evidence/task-gd/gd-<3x1|4x1>-<tcp|rdma>.json --gates <list> --allow restart,turnover,remount`. K42: `gd-4x1-rdma.json` with `--gates identity,topology,posix-durability,e1-manifest,e2-client-stop,b6-member-down,c5-protocol-live,d1-packing,d3-efs-load,e4-scale`. K106: `gd-3x1-<tcp|rdma>.json --gates identity,topology,k106-halt`. K15: `--gates identity,topology,k15-w52,k15-stepdown`.
3. Own runs (K112, K110, K43): `scripts/evidence/task-gd/run_h.sh <run> fcstor012 <tcp|rdma> scripts/evidence/task-gd/h/<file>.cmds` with `k112-rdma.cmds`, `k110-tcp.cmds`, `k110-rdma.cmds`, `k43-rdma.cmds` (TCP in fact), `k43-rdma-keep.cmds`, `k43-rdma-variant.cmds`.
4. Output lands in `/tmp/gd/out/<run>` (override with `GD_OUT`) and is streamed by [`push.sh`](../../../scripts/evidence/task-gd/push.sh) to `~erbmi1/efs-artifacts/taskGD-20261111/<run>/` with `SHA256SUMS`. Expected checks: every gate PASS, every `session revoked at unmount` line `rc=0`.
5. Cleanup: delete `/tmp/efs-taskGD`, `/tmp/efs-taskGD-tmp` and the build tree on each host; close the Mac masters.
