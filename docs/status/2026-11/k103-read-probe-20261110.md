# K103: the Raft read probe a compacted follower always rejected (Task FG)

**Verdict: PASS. K103 is FIXED on the branch (not merged), blocks alpha: no. A follower with `snap_idx > 0` answers the
leader's zero-prefix read probe as a leadership acknowledgement; the probe reply moves no `match_index`, `next_index` or
commit and triggers no resend. On node9900 the live arm went from 26,368 to 83 follower rejections in a 30 s read window
(zero-prefix probes 28,244 to 0 in the classified pair), `make test` and `make asan-check` are rc 0, `make tsan-check` is
rc 0 on its second run (the first failed `k37_segment_rebuild`, see the gates paragraph).**

## The three questions

(a) **What a read probe must prove.** For ReadIndex the follower's answer must show that, when it processed the probe, it
was in the leader's term and accepted the sender as leader. Nothing about the log: the probe has `prev_index 0`, no
entries and `leader_commit 0`. The leader still needs its own apply barrier (`last_applied >= read_index`) and a quorum of
such answers for one round before the read may complete.

(b) **How the leader recognises a read-round acknowledgement.** By the echo of the round: `send_msg` stamps
`last_log_index = read_round` on every AppendEntries while `read_in_flight == 1`, and a follower copies it into its reply.
`on_ae_rep` sets the peer's `read_acks` bit only inside its **success** branch when `read_in_flight == 1`,
`in->last_log_index == read_round` and the peer is a voter; the host fast path `efs_raft_read_control` does the same for a
successful reply that matches the round and the configuration. A rejection never counts.

(c) **Which reply fields move leader state.** `success` selects the branch. On success: `match_index` raises
`match_index[peer]` only if larger, `next_index` is raised (never lowered) to `match_index + 1`, `try_commit` derives the
commit index from the match quorum, `busy` sets the hold-back, `vote_granted` (echoed) marks a probe so the reply does not
clear `ae_inflight`. On rejection: `match_index` is a hint, `next_index = hint + 1`, `peer_rejects++`, then `send_snap`
(hint at the floor), `send_ae_behind` or `send_ae`. `term` steps the leader down. So the same four fields mean "I hold the
log through here" on success and "restart from here" on rejection, and a probe has nothing to say in either sense.

One correction to the K38 page. It says a compacted follower's probe "can never be an acknowledgement". The host fast path
(`efs_raft_read_control`) has no `snap_idx` test and has always acknowledged a zero-prefix probe on a compacted follower.
The rejection happened only for probes that reached ordinary receive (`on_ae_req`): a missed receiver `trylock`, pending
inbox work, a receive in progress without `recv_vote_safe`. Under load that is most of them, which is why the rate was so
high (see the table).

## The change

```
on_ae_req:  if (in->prev_index < r->snap_idx && !is_read_probe(in))   /* was: no is_read_probe */
is_read_probe(in): vote_granted == 1 && !nentries && !prev_index && !prev_term && !leader_commit
on_ae_rep (success branch): the send_ae(data_only) kick is skipped when
           vote_granted && match_index <= old_match   /* a probe ack that proves nothing new */
```

A probe now takes the path an uncompacted follower already took: nothing is appended or truncated, `leader_commit 0`
moves no commit, `log_term(0)` matches, the reply is `success=1, match_index=0, busy=follower_busy()`.

Why each property holds:

1. **A same-term follower with `snap_idx > 0` acknowledges the zero-prefix probe.** The exemption sits after the
   stale-term refusal and after the `resync_requested` refusal, and before the compacted-prefix test, so only that test
   changes. Test: `test_read_probe_compacted_reply` kind 0, whole and batched receive (`cap_ok`, `cap_match 0`, the
   read context echoed, no rejection counted).
2. **The reply changes neither `match_index` nor `next_index`.** It carries `match_index 0`; the leader raises match only
   above the current value and raises next only to `match + 1`. Test: both peers' `next_index`/`match_index` equal before
   and after the round (`test_read_probe_compacted_follower`, with and without an unsent leader tail).
3. **It never advances commit.** The follower applies no commit (`leader_commit 0`); the leader's `try_commit` sees an
   unchanged match quorum. Test: `efs_raft_commit` equal after the round.
4. **No `send_ae`, `send_ae_behind` or `send_snap` because of a probe reply.** All three are reached from `on_ae_rep` only
   after a rejection, which a success is not. The success branch also kicked `send_ae(data_only)` whenever
   `next_index <= own last index`; the test with an unsent leader tail showed it: the probe ack shipped that tail
   (`match 11 -> 12`, `batches 11 -> 12`) before the guard. A probe ack that proves nothing new now ships nothing; batches
   go out on the batch acks, proposals and heartbeats that own them. Same-shape replies in the code: `efs_raft_read_control`
   already treats them as `known_probe` and returns before any send. Tests: `n.batches[]`, `batches_sent`, `snap_chunks`
   and `ae_requests` unchanged but the one probe per follower.
5. **A follower in a newer term still refuses and the leader steps down.** `maybe_step_down` and the stale-term refusal come
   first and are untouched. Test: `test_read_probe_newer_term_steps_down` (a guard: it also passes before the fix).
6. **An ordinary AppendEntries with a compacted `prev_index` is refused exactly as before.** The predicate requires the
   probe marker and an all-zero prefix with no entries and no commit. Tests: a data heartbeat (`vote_granted 0`) and a
   commit probe with `leader_commit > 0` at a compacted prefix are still refused with `match = snap_idx`; the existing
   `test_snapshot_rejects_delayed_compacted_prefix` (entries, prev 4 with a wrong term, no marker) passes unchanged.
   The predicate does not test `last_log_index`: the leader stamps none once the round has its quorum
   (`read_in_flight == 2`), and the follower's answer to that probe is the same.

Limits, stated: a follower ordered to resync (`resync_requested`) still refuses the probe, deliberately: its rejection with
match 0 is the documented channel that makes the leader send the snapshot. A commit probe (`send_commit_probe`) whose
prefix is older than the follower's snapshot is still refused, by design: the hint rebases the leader. The one collision is
a commit probe with match 0 and commit 0, indistinguishable from a read probe on the wire; it now succeeds, which changes
nothing (commit 0 means nothing is compacted yet).

## Before and after

Unit cases (`tests/test_raft.c`, three cases, run in both fixture modes): on the unchanged `raft.c` at the tests-only commit
`b3d5cf498`, 42 `FAIL` lines (the follower logs a `prev-compacted` rejection, the leader counts a peer rejection and
rewrites `next_index`, the resend adds an AppendEntries with entries, the probe's reply is `success=0` with match
`snap_idx`; the stale-term case passes, it is a guard). After the fix: `test_raft: OK` in both modes. One thing the
before run does **not** show: the read round itself still completes before the fix, because the resent batch's reply
carries the read context and counts. So "the read completes on the probe replies alone" is asserted together with
"no entries were sent", not alone.

## Reproduction

Prerequisites: a Linux host with the build dependencies (`EFS_FUSE_PREFIX` as on node9900), a `git archive` copy of each
tree (`9403d0666` for before, the branch head for after), nothing else on the host that needs the cores.

```
cd <tree> && make -j8 test-bins tests/faults/efsd efsd efs-fuse efs-bench efs-mgmt
# unit cases, both fixture modes (the second routes replies through the host fast path first)
./tests/test_raft test_read_probe_compacted_follower test_read_probe_compacted_reply test_read_probe_newer_term_steps_down
EFS_TEST_EARLY_READ_ACK=1 ./tests/test_raft
# before the fix: check out tests/test_raft.c from b3d5cf498 over the unchanged raft.c; the three cases print 42 FAIL lines
# live arm (the same script drives either build through --tree; ~2.5 min each, needs ~600 MB in TMPDIR)
python3 scripts/evidence/k103/read_probe_live.py --tree <tree> --out before.json   # tree = 9403d0666 build
python3 scripts/evidence/k103/read_probe_live.py --tree <tree> --out after.json    # tree = branch head build
# gates
make test; make tsan-check; make asan-check
```

Expected: the unit cases `OK`; the live arm prints `follower_rejects_in_window` (tens of thousands before, tens after, all of
them data batches and commit probes). Cleanup: the script removes its work directory unless `--keep`.
