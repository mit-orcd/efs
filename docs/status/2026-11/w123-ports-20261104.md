## Regression found and fixed

The first gate had 1 FAIL: `tests/test_report_stepdown.py` (`step-downs` had 2
of the required 3 events). Solo: 3 of 3 FAIL on the ported tree. Devel
(`ae217a051`) passed 3 of 3 (35.6 / 40.3 / 95.9 s). Devel plus only the
`raft.c` commit failed 2 of 2, so the raft fix is the cause: the appends drain
faster and the 400-record workload ended before the third step-down round
(the loop stops when the writers exit). With 800 records per writer the test
passed 3 of 3 solo (44.8 / 44.9 / 45.8 s); `0d9a79fff` made 800 the default on
the branch. The product behaviour is the intended one (fewer stalled
heartbeats); only the test's load was too short. Wave 56 took Task DA's fix
instead (`030e35e19`: writers run until the schedule has run), so the record
count is no longer a tuning knob.
