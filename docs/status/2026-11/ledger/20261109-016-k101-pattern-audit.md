# K101 pattern audit of the FUSE client's per-caller caches (Task EO)

[K101 pattern audit of the FUSE client's per-caller caches (Task EO)](../k101-pattern-audit-20261109.md): **PASS, no defect found, audit only, no source or test change, no K row, blocks alpha: no** (Nov 9, branch `claude/optimistic-murdock-ac0414` on devel `33cd0a839`; not merged, not pushed). The audit asked K101's two questions of every table or cache in `src/client/efs_fuse/` and `src/client/`: is the match key short, and is an entry matched again after the mutex is released? Only the query snapshot RPC carries the caller's groups. `.find` is fixed by K101, and `.stats` keeps no cache. The virtual query inodes are keyed by the result bytes and intern under one hold. The LOOKUP memo, open-reference table, write-back pool, READDIR listing, lock table and client library caches hold rows that GETATTR, LOOKUP and READDIR return the same way for every caller, and permission is checked per request on the client against a fresh row. The page has one table row per cache with file:line evidence. Not run on node9900 (no reproducer was needed). One limit: if NFS re-export is turned on (W152, outside alpha), GETATTR could report the pinned length of another identity's `.find` result.
