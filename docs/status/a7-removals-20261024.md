## Direct I/O

- **One layout.** Every fragment file (chunk and segment) is opened with
  `O_DIRECT | O_CLOEXEC` (`server_frag_open`) and is payload padded to 4 KiB
  followed by one 4 KiB tail page that starts with the I25 record. Reads use
  an aligned bounce (`server_frag_pread`). A file of any other size, such as
  the removed buffered layout (payload plus a bare 128-byte record), is not
  this build's format: GET answers INTEGRITY and GC refuses it
  (`test_store_gc`, `fragment_tail_smoke.py`).
- **Small and unaligned operations.** Unaligned or short sources go through
  a per-thread aligned bounce buffer and are zero-padded; the record goes on
  the aligned tail page. `test_store_overwrite` writes and reads back 1003-,
  4096+1-offset-, 7003- and 10-of-8192-byte payloads, grows and shrinks a
  file, and checks every byte of the image.
- **Startup refusal.** Before anything else touches a root, efsd writes and
  reads back one aligned page under `ROOT/data` and stops on failure:
  `storage root R refused: fragment I/O requires O_DIRECT (O_DIRECT open of
  ...: Invalid argument)`. Linux 6.6 and later accept `O_DIRECT` on tmpfs, so
  the test mounts `tests/nodirect_fs` (a FUSE passthrough that answers
  `O_DIRECT` opens with `EINVAL`); it checks one root and the second of two,
  that no probe file is left, the three removed flags, and that an ext4 root
  serves (`direct_io=on`). Without `/dev/fuse` or `fusermount3` it reports
  NOTRUN; there is no fallback. Tests that ran buffered on hosts without
  `O_DIRECT` keep running: their stores live under `TMPDIR`, which supports
  `O_DIRECT` on amd (ext4 home, tmpfs `/tmp` on kernel 7.0; other hosts not
  checked here); a host whose `TMPDIR` cannot do it fails those tests at
  startup with the message above, never silently buffered.
- **Durability barriers (audit).** `O_DIRECT` bypasses the page cache, not
  the device cache or the inode size. Every barrier that existed stays;
  none depended on the buffered path:
  1. PUT with a sync root (`finish_fragment_put`): acknowledged after the
     write; durable at the root's barrier, `syncfs(root)` then the epoch
     record rewritten and `fdatasync`ed (`put_sync_barrier_locked`); a client
     COMMIT waits for it (`server_put_sync_commit`).
  2. PUT without a sync root: `fsync(file)` and the containing directory and
     unproven ancestry (`sync_fragment_parents`).
  3. Packed segment PUT (`sg_write`): `fsync(file)` and `sg_sync_path(dir)`
     before the ACK.
  4. Rebuild PUT (`dg_put_fragment`): `server_put_sync_commit` before the
     degraded mark is cleared.
  5. GC and reclaim: directory `fsync`/`syncfs` before an ACK
     (`gc_sync_directory`, `fragment_parent_sync`, reclaim journal `fsync`,
     two `syncfs` per checkpoint).
  6. Stop: `syncfs` plus a clean epoch record per root (`server_put_sync_stop`).
  7. Benchmark only: `O_SYNC` opens; a length change still takes `fsync`.
  `finish_shard_write` keeps an explicit `fsync` for every production
  same-length rewrite, as before (`test_store_durability`: one file sync and
  the directory syncs for aligned and bounce writes, with fault refusal).

## Metadata leadership (A9 part)

The co-location pump is gone; elections alone place the leaders. `efs-mgmt
status` adds one section, each member reporting its own role (format; one
line per member, then a summary; competing claims and leaderless groups get
their own lines):

```
Metadata leader placement (self-reported):
  node N: leads none | leads group G (term T)[, group G (term T)] | down | unreachable
  leaders: L/G groups on D distinct node(s); R/M members reported
```

`raft-status` also prints `leaders group0=nodeN group2=nodeM` as that node
sees them. In `test_k33_growth.py` at eight members, elections alone left
both group leaders on node 3 (one run). Elections do not guarantee spread
leaders; the metadata-distribution roadmap stays open (D42).

## Expiry: what remains and why

**Superseded by [D43](decisions.md#d43--efs-and-expiry-ship-in-alpha-10-user-oct-25)
(user, Oct 25): expiry ships in alpha 1.0.** The `EFS_BUILD_EXPIRY` switch,
its `#if` guards and `make test-expiry` are removed; expiry compiles into
every build and its only control is the cluster expiry policy

`EFS_EXPIRY` stays refused at startup and now names that command. The
tests are back in `make test-all` and the live fixture is the `d5-expiry`

out (`src/meta/expiry.c` not linked; worker, clock, RPCs, Raft commands,
namespace hooks and the six `efs-mgmt` expiry commands inside
`#if EFS_BUILD_EXPIRY`; expiry opcodes refused with `EFS_ERR_UNSUPPORTED`);
the opcode and KV-kind numbers stayed reserved, which is why D43 could

`735b82562`: 4 PASS.

## Transport

`efs_transport_startup()` runs in efsd and efs-fuse: an unknown
`EFS_TRANSPORT` and an explicit `rdma` without a usable device (the
`EFS_RDMA_DEV` device, else the first active one) stop the process
(`EFS_TRANSPORT=rdma but no usable RDMA device ...; refusing to start`).
`auto` logs `transport auto: rdma on DEV` or `transport auto: tcp (no usable
RDMA device)`, and each connection whose upgrade fails in `auto` says it
uses TCP (bounded). Before this change an explicit `rdma` on a host without a
device kept TCP connections, because the upgrade was never attempted.
`test_transport_select.py` covers both binaries; on amd `auto` chose
`rdma on rxe0`.
