### K11 case

`--put-barrier-fault` fails at `tests/live/put_barrier_fault.py:32`: with the fault marker set to `all file`, the client `fsync` returned success (`AssertionError: None`), and no daemon log contains `test-store-barrier: refusing fragment`, so the LD_PRELOAD shim never refused anything. No data was published wrongly and nothing was lost; the case did not get as far as its publication-state check. This is not the K11 symptom (no `rc=-9`, no missing fragment).

Likely cause, not proven: the shim (`tests/live/store_barrier_fault.c`) refuses only `fsync()` on regular files under `/data/exports/`. Since the A7/D42 change (`735b82562`, Oct 24), a PUT on a root with a sync record acks after `finish_shard_write(fd, bytes, 0, 0)` plus `put_sync_note` (`src/server/store.c`, `finish_fragment_put`), which defers the file barrier to the root's batched barrier. The gate's fault injection no longer sits on that path. Follow-up: confirm by tracing which call the batched barrier uses, then either point the shim at it or move the case to the new barrier, and add `--put-barrier-fault` to the driver's `gc_args` so F4 runs the K11 case. Until then K11's invariant is not demonstrated by F4.
