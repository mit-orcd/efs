## What changed

| area | change |
| --- | --- |
| reductions | REDUCE payload 24 B (times and `mtime_gen`); a reduction with `max_end` is refused; folds no longer touch `max_end` |
| lane adoption | `lane_adopt()`: a newer epoch clears the lane's `max_end` and bumps `seq`; used by publish and the truncate tail write |
| EOF filter | getattr and `collect_phys_eof` count a lane's EOF only when the lane's epoch equals the inode's |
| BOOTSTRAP | new `EFS_MD_CMD_BOOTSTRAP_LANE` (79, 26 B) on the lane group; REPORT proposes it before the first publish on a cross-group lane; a lane-local publish to an unstamped lane answers BUSY |
| ACTIVATE | only the epoch-checked 25 B form (plus session) is accepted |
| GETCHUNKS | captures inode epoch and fence history coherently (`efs_meta_get_inode_authority_tx`), builds each view from them (`efs_meta_get_chunk_view_auth`), rechecks, retries at most 4 times |
| client | a successful GETCHUNKS drops local entries of covered chunks it did not return, if unchanged since the pre-RPC snapshot |

The gate script starts and formats the cluster, mounts A and B, runs the

## Findings

1. **Pre-existing peer resurrection (fixed here).** On the unchanged
   release, `pull_chunks_range` (`src/client/ops.c`) kept local entries for
   chunks a successful GETCHUNKS no longer returned and marked the range
   fresh, so mount B served a peer-truncated chunk's old objects until GC
   deleted them (g4.3, g5.1). The fix drops such an entry only if its read
   key is unchanged since a snapshot taken before the RPC, so a concurrent
   local publish is kept.
2. **Audit correction.** An open descriptor keeps its mount's size by
   design (`efs_fuse_getattr_ino`, "Open-fd size stays local"); the
   protocol's §3.5 and §8.2 now say so, and g5.1 checks that promise.

## Limits and remaining gates

- Truncate is still the old eager path (LANE_FENCE deletes), so lanes never
  lag in production yet. Adoption and the floor are exercised by unit
  tests that move the inode epoch directly; lazy interleavings (writes on
  not-yet-adopted lanes, delayed BOOTSTRAP across a sweep and retirement)
  need step 3.
- The history revision is not yet stored. The inode epoch is the cache and
  view key until retirement exists (step 4), and the revision lands with
  the history format change in step 3.
- The staged durable-publication path (lane writer views, LANE_AUTHORITY,
  lane-bootstrap transactions) has no FUSE callers and still uses the lane
  stamp; it is removed with the destructive path in step 5.
- One run per configuration; TCP only; no RDMA, fault injection or
  restart-under-load in this step.
