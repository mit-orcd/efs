## Defects found

1. **Live harnesses still expected protocol 4 (fixed, `2791f211d`).** K13
   raised the protocol to 5 and updated the declarations, but eight
   harnesses (`tests/live/expiry_lifecycle.py`, `fragment_integrity.py`,
   `fragment_tail_smoke.py`, `gc_reclamation.py`, `io_stats_smoke.py`,
   `query_rpc.py`, `raft_read_freshness.py`, `scripts/w127_incompatible_entry.sh`)
   asserted a reply of version 4. The expiry fixture's first run stopped at
   "declaration refused". New fast test `tests/test_live_protocol_version.py`
   ties every hand-built declaration to `EFS_PROTOCOL_VERSION` (fails on
   the old harness).
2. **The intel hosts' devops copy was a dangling link** (outside Git):
   `/data1/efs/devops` pointed to `releases/85f2a199aa39/devops`, gone since
   Oct 14, so `deploy.sh`'s devops push landed nowhere and
   `smoke-persist.sh` was missing on the hosts. The link was replaced by a
   directory on both hosts and the devops scripts pushed; durability then
   passed.
3. **`gc_reclamation.py` hand-builds an unticketed PUT (open, W158).** Its
   "valid late-PUT control" (line ~2945) sends a PUT without an admitted
   ticket; since K13 storage refuses every unticketed PUT (reply status 1),
   so the assertion `reply[:2]==bytes([7,0])` fails. The daemon is right;
   the harness must admit a ticket first (or use the ticketed client path).
   Until then the expiry suite is NOTRUN beyond that step.
