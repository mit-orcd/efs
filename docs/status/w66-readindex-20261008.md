# W66 — fresh ReadIndex behind outstanding replication

Working branch: devel-w66; isolated checkout /tmp/efs-w66-20261008.
Base: 532660e3, current merged devel when work began.

## Confirmed defect and fix

An unanswered entry batch sent before a new ReadIndex round carries an older
or zero read context. `send_ae` suppressed sending while that batch was fresh
and commit had not advanced. The new read therefore lacked an eligible quorum
message and could wait for a later timer heartbeat. A delayed data ACK alone
cannot authorize the post-admission round.

While beginning/broadcasting a pending read round, send a context-bearing empty
probe even if commit is unchanged. Reuse existing commit-probe semantics:
follower prev-index/term validation, durable follower processing, and a marker
that prevents its response from clearing the outstanding entry window. No
persistence barriers, current-term checks or post-admission freshness rules are
removed. No extra data window is sent.

The deterministic regression fails against baseline and passes with the fix;
the complete in-memory Raft suite also passes strict Clang warnings and
ASan/UBSan. [Evidence](../../results/measure/20261008-w66-readindex/README.md).
This does not establish that the NUC group-2 latency split has this sole cause.
