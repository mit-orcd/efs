# orcd-mini profile under the user's workloads, `9099380f3` — 2026-10-17

**Profiling only (no code change). The cv_mu wake-up fix holds under load:
its re-acquire waits dropped out of the leader's top lock waits (45% of them
on `f4a373b13`). Lock waits are now 15.6% of leader context switches.
Nearly all of them are `h->mu` on write/proposal paths, so this profile is
the fresh live baseline for step 1 of the
[Raft host mutex plan](raft-host-mu-plan-20261016.md).**

Previous profile: [`f4a373b13`](orcd-mini-profile-f4a373b13-20261016.md).

## Environment and workload

orcd-mini on `9099380f322a` (daemons and both clients): three efsd on
node9901, RDMA mlx5_0, direct I/O, files engine, `.efs` on. Node 3 leads
both groups (terms 141 and 143). Sampled 2026-10-17 from 21:20Z, passively
(non-root `perf` on the existing PIDs).

The user's workloads ran on both clients:

| Client | Workload | Rate (`/proc/PID/io`, 20 s) |
| --- | --- | --- |
| node9900 `/data1/efs/orcd-mini-mnt` | `tiny_files.py --workers 16` writer | 933 write calls/s |
| node9900 | `edelete --force --delete tiny-files2/` | not measured |
| node9900 | `ecrawl --no-write` | not measured |
| node9901 `/data1/efs/mnt` | `tiny_files.py --workers 16` writer (100M-file target) | 745 write calls/s |
| node9901 | `tiny_files_md5.py tiny-files3` reader | 609 read calls/s |
| node9901 | `ecrawl --no-write` | not measured |

This is heavier and more mixed than the `f4a373b13` sample: two writers,
an active delete and two crawlers.

## Leader lock waits (`h->mu`)

DWARF-unwound context-switch capture
(`perf record -e cs --call-graph dwarf,16384`, 3 s, leader efsd):

| Share of lock waits | Site |
| --- | --- |
| 27.9% | submit: `host_propose_impl` (15.5%) and propose-wait (12.4%) |
| 13.9% | client REPORT (`server_raft_host_report`) |
| 12.7% | retained CREATE: `host_leader_cover_pick` (8.9%) and `host_wait_verdict` (3.8%) |
| 7.7% | unlink proposal (4.3%) and `host_wait_verdict` (3.4%) |
| 4.8% / 3.9% | `host_pub_batch_propose` / `host_create` proposals |
| 3.2% / 2.3% | LOOKUP / GETATTR lane reads |
| 2.2% | `host_pump` |

The order matches the plan's sequence:
- per-phase timing first (step 1);
- a routing snapshot for `host_leader_cover_pick` (step 2);
- then reassess REPORT (step 4).

Unlink and verdict waits appear now because this sample includes an active
delete.

## Reproduce

From the Mac, while workloads run, with the scripts stored next to the raw
captures:
1. `orcd_prof.sh OUT` (commit rates, on-CPU for the daemons and the node9900
   client).
2. `cs_prof.sh PIDS DIR` on the daemons and each client.
3. `dwarf_lock.sh DIR` on node9901 (leader DWARF lock waits).
4. The 200-file `probe.py` on each mount.
5. `/proc/PID/io` deltas for the workload processes.

## Limitations

- The workloads are uncontrolled and differ from earlier samples. Rates and
  latencies are not a before/after performance comparison.
- The `edelete` and `ecrawl` rates were not measured; workload syscall
  tracing is not permitted.
- The samples are single 3–30 s snapshots.
