  the real `server_start_rejoin`/`server_stop_rejoin` from `cluster.c`, parks
  the rejoin worker, and asserts failed start, duplicate start, teardown

## Interaction with K54 (member-down clean unmount, OPEN)

K54 is the client's session revoke failing at `phase=storage-fence`
(`src/common/session_revoke.c`, `raft_host.c` storage-fence), i.e. a client
stop with a member down. F24 only changes `efsd` daemon teardown (who joins
the rejoin thread) and F35 only the `raft-resync` management command; neither
touches the revoke/fence path, the flush/settle path or member-down detection.
No interaction found and neither is a K54 fix; K54 stays OPEN, blocks alpha:
yes. One adjacent note: F24's `rejoin` phase makes a member's own shutdown wait
for an in-flight HELLO (bounded by the existing shutdown deadline), which does
not change what a clean *client* unmount observes.
