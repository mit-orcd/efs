# K87: Task CI

- State: FIXED
- Blocks alpha: no
- Kind: durability / PUT syncer

## Item

Task CI: after `syncfs(root)` failed, the per-root PUT syncer in `efsd` (`store.c` `put_sync_thread`) retried it with no pause: the failed epoch's fragments stayed counted and old, so the thread was due on every loop pass. Measured on intel1 with CG's shim refusing node 1's barrier: one thread at 99.7% CPU (one of 8 cores) and at least 14,000 attempts/s (`strace`, a lower bound) for as long as the fault lasts; the daemon log itself did not flood (it logs the failure once), only a shim that logged per attempt did (15,000 lines/s in CG's first version). A failing disk would have spun a core on the node and hammered the device with `syncfs` while COMMIT and `fsync` already answered EIO.

## Disposition

FIXED, blocks alpha: no (the refusal was correct and data was safe; the cost was a burned core and repeated `syncfs` on an already failing root); retry delay doubles 50 ms..2 s and resets on a successful barrier, repeat log at most once a minute with a count; unit check in `tests/test_store_durability.c`; after: 16 attempts in 30 s, 0.4% CPU ([evidence](../2026-10/syncer-retry-backoff-20261031.md)).

## Finding on devel

FIXED, blocks alpha: no; failed root `syncfs` retried with 50 ms..2 s back-off instead of a tight loop, repeat log once a minute ([evidence](../2026-10/syncer-retry-backoff-20261031.md))
