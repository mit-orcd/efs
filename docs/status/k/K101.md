# K101: Task EC (found by the before-reading of the `.find` result cache ownership pilot)

- State: FIXED
- Blocks alpha: no
- Kind: client / FUSE `.find`

## Item

Task EC (found by the before-reading of the `.find` result cache ownership pilot): an `.efs/find/<term>` operation fetched and stored the server result in one critical section of the cache mutex and matched it again by directory, term, uid and gid in a second. The match ignored the supplementary groups the server authorized the fetch with, and a concurrent fetch of the same directory and term could replace the slot in between. (F1) A caller could be served the result fetched for the same uid and gid with another group set: names visible only through a group it does not hold. (F2) After a fetch by another uid, or an eviction, the caller found no slot: GETATTR answered `EPERM` (`find_query_len`'s `-1`), LOOKUP and OPEN `EAGAIN`. Found by reading the code; no incident traced. Reproduce: `same_term_pairs` of `tests/test_find_res_interface.c` against `src/client/efs_fuse/find_res.c` of `111594fb4` (3 of 3 runs: 517 to 669 of 3,000 OPENs per thread served the other group set's result, 991 to 1,121 misses per thread).

## Disposition

FIXED, blocks alpha: no; each operation reads the slot its own fetch filled before the cache mutex is released, so no match and no miss remain (Task EC fix commit); `same_term_pairs` 0 served and 0 misses after; `make test`, TSan and ASan `find_res_interface` on node9900 ([evidence](../2026-11/find-res-ownership-20261108.md))

## Finding on devel

FIXED, blocks alpha: no; an `.efs/find` operation is served only the result its own fetch stored (same critical section), never another group set's result or a miss turned into `EPERM`; `same_term_pairs` in `tests/test_find_res_interface.c` fails before and passes after on node9900 ([evidence](../2026-11/find-res-ownership-20261108.md))
