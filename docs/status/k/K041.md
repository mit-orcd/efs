# K41: Packer writes a segment degraded to a member stopped 27 s earlier

- State: VERIFY
- Blocks alpha: unstated
- Kind: single-loss durability of acknowledged small files, alpha blocker candidate

## Summary

- Cause: Fixed: heartbeats probed members serially with 30 s timeouts so the leader never marked the stopped node down; heartbeats are now parallel and the packer probes destinations.
- Owners: `efs_pack_destinations`
- Reproducer: `test_k41_packer_placement.py`, `tests/test_k33_growth.py`.
- Invariant: The packer places only on members the leader knows live and replaces a refused destination with a live spare rather than writing degraded.
- Owed: Live multi-host, RDMA and orcd-mini gates (the test-defect fix `fd50deb31` is merged, wave 71).

## Item

The packer placed a segment fragment on a member that had been stopped 27 s earlier and wrote the segment degraded (two fragments, `packer: segment g0 ... written degraded: fragment 0 for node 1 not acknowledged (rc=-6)`); the files it packed were fully protected before packing. The group leader (node 2, 8-member loopback, `tests/test_k33_growth.py`) never logged `heartbeat: node 1 ... marked down` while three other members did within 7 s, so `efs_pack_destinations` still counted node 1 live; when the test then wiped node 5 (the segment's second holder) seven seconds later, a fresh mount read the 2-byte file `EIO` (`fetch published ... rc=-6`): one fragment left, nothing to rebuild from. Reproduced 1 of 3 alone on intel2 and once in the wave-9 merge gate, both times with the group leaders spread (group 0 on node 2); passes with both groups led by node 3. Latent since K37 let the packer write degraded (wave 6); the test began to catch it this wave
