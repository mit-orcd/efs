# K119: A failed snapshot import blocks the member until a leader sends an image

- State: OPEN
- Blocks alpha: no
- Kind: server / Raft snapshot import, failed state

## Summary

- Cause: By reading: after a failed import the group stays in the FAIL state, which only a snapshot chunk from the leader clears; until then applies stay blocked and, since wave 80, the member does not campaign.
- Owners: `src/server/raft_host.c` (`host_snap_import_pump`, `host_snap_import_pass`, `snap_import_poll`, `snap_import_pending`)
- Reproducer: not determined (no test): fail an import (full disk or a bad image), then stop the leader or move leadership to a member whose log still covers the follower.
- Invariant: A failed import ends in a state from which the member applies and campaigns again without a restart, or asks for a new image itself.
- Owed: The pump clears FAIL itself (the import pass writes nothing to the store before DONE, by the review) and asks for a resync; a test of that path.

## Item

K113 round 3 verification review (Nov 11, by reading): the pump acts only on a finished import. A failed one (the local export out of space, a bad image) leaves the group in the FAIL state, which is cleared only when the leader sends chunk 0 of an image or retries the closing chunk. If the leader is lost, or leadership moves to a member whose log still covers this one so that it replicates by AppendEntries and never sends an image, the member keeps its applies blocked. The apply block in that state is older than the K113 fix; the fix adds that the member also does not campaign while an import is pending, FAIL included. With a second member down the group stalls at this member's unapplied bound; a restart of the member heals it
