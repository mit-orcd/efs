## Item

Task EW (orcd-mini batch O, candidate `9bb50fe79`, Nov 9): after an `ior hard` run failed with `EIO` (K38) and its file was removed, the node9900 RDMA client kept the failed PUT/REPORT state of the deleted inode and retried it forever: `dcache-flush-fail ino=6980 stage=put rc=-3` (`EFS_ERR_NOT_FOUND`), `report-sync-fail ino=0 stage=held-unit-flush rc=-3`, `background-pressure ino=6980 rc=-3 retained`, every few milliseconds for 25 minutes. A plain `client.sh stop` was refused after 60 s (`stop-refused: unresolved writes or lease releases remain; mount retained (retained-releases=0 wb-pending=0)`: the counts it prints do not cover the state that blocks it); `--force-discard` returned rc 1 after 60 s (`unmount not clean: flush rc=-3 settle rc=0 revoke rc=0`; the session revoke itself succeeded). Two later two-client shared-chunk runs on that client got `EIO` (cause unproven; two earlier ones on it passed) ([evidence](../2026-11/orcd-mini-batch-o-20261109.md))
