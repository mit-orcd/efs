# K114: Reply waits outside the K106 (a) cut still last the 30 s timeout

- State: OPEN
- Blocks alpha: yes
- Kind: availability with one member unresponsive

## Summary

- Cause: The K106 (a) cut covers only reads and the four directory mutations with an op-id on TCP connections; every other reply wait on a halted member still lasts `EFS_IO_TIMEOUT_MS` (30 s).
- Owners: `src/client/node_cache.c`, `src/client/inode_rpc.c` (`rpc_reply_wait_cut`)
- Reproducer: not determined (no test); the design study names one per group: SIGSTOP the leader, SIGCONT it after the cut, and check that the effect happened once.
- Invariant: While one member hangs no operation in flight waits the 30 s transport timeout or fails, for every request type and on every transport.
- Owed: Fix tasks from the design: cut truncate, APPEND, CREATE_RETAINED, REPORT with a publication id; an identity first for chmod, chown, utimens, XATTR, HOLD, FLOCK; blocking FLOCK, RDMA, a dead host stay uncovered.

## Item

Wave 79 merge (Nov 11), split from K106 when its part (a) was fixed for the covered waits: the cut of a reply wait on a halted member applies only where a retry on another member is known to be safe, which is reads and the four directory mutations that carry an op-id, on TCP connections that go through `rpc_send_recv_shard_once`. Not covered, and still waiting the 30 s transport timeout: mutations without an op-id (SETATTR, APPEND, HOLD, REPORT_CHUNKS, FLOCK, XATTR set and remove, CREATE_RETAINED), RDMA connections, `rpc_send_recv_dual_once`, the other receive sites in `src/client/inode_rpc.c`, and the PUT, read and data-commit receives. A powered-off or partitioned host is not covered either: the probe's connect times out, the verdict is failed and not silent, and the wait stays 30 s; the same holds for a request whose deadline is less than 5 s away

## Disposition

OPEN, blocks alpha: yes (Nov 11, wave 80, Task FY, [design study](../2026-11/k114-uncovered-waits-design-20261111.md), by reading, nothing run): devel already sends every request type again after a failed receive, so a cut changes the timing and adds the false cut of a slow member. Safe with an identity that exists: SETATTR truncate (truncate receipt), APPEND (receipt), CREATE_RETAINED (directory op-id window), REPORT with a publication id. Not safe: chmod, chown and utimens (the op-id on the wire is not recorded in apply), XATTR set and remove, and FLOCK, where a delayed repeat can undo a later change. No fix task is started yet. Was: OPEN, blocks alpha: yes (coordinator's ruling at the wave 79 merge: it is the rest of K106, whose invariant is inside the one-member-down promise; the user may overrule): no fix; the list comes from Task FR's page and two reviews, by reading ([K106 (a) page](../2026-11/k106a-inflight-wait-20261110.md); [ledger](../2026-11/ledger.md))
