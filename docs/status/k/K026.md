## Item

LeakSanitizer aborts on node9900/node9901; F1 needs a working leak check. On the efs1–3 build VMs (Fedora 42, aarch64, 1 GB RAM, tmpfs `/tmp`): `test_reclaim` and `tests/test_server_processes.py` failed on pristine devel and on every K branch. Cause found Oct 22: efsd's capacity headroom rule (`storage_capacity.h`, 20% free) refuses the 972 MB tmpfs `/tmp` and the 88%-full root disk ("Storage quota: cannot establish safe headroom; refusing startup"); both PASS with `TMPDIR=/data1/tmp` (the 20 GB XFS data disk), the full documented toolchain was applied on all three on Oct 22 (kickstart package set, devops build deps, `devops/profiling/HOST-SETUP.md`: perf, bpftrace, sysstat, fio, iperf3, blktrace, numactl, trace-cmd, dwarves, gdb, valgrind, sanitizer runtimes, glibc debuginfo, profiling sysctls, memlock, perf group with tracefs, cache-drop helper); Tart VMs expose no hardware PMU, so `perf` samples `cpu-clock`, not `cycles` (the W138 TSan gate failed without `libtsan`), and the root disks run full (old build trees under `~/build` must be deleted). Tests that hard-code `/tmp` instead of honouring `TMPDIR` (for example `test_query_disk`) leave stale `efs-*` directories that fill the tmpfs (857 found on efs3 on Oct 22); making every test honour `TMPDIR` and clean up is a K25-class harness item. The merged devel of Oct 22 was otherwise clean on efs1
