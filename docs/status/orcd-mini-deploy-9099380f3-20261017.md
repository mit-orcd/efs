# orcd-mini deploy 9099380f3: "not indexed yet" for .efs commands — 2026-10-17

**PASS. Deployed to orcd-mini as `9099380f322a`; every POSIX suite passes,
with no failures.** `.efs` commands on a directory newer than the published
catalog now answer immediately with a clear message instead of EBUSY.

Linked item: the `posix_extras` failures in the
[8ad79fcd5 qualification](orcd-mini-deploy-8ad79fcd5-20261017.md). There,
`.efs/stats` and `.efs/find` on a just-created directory returned EBUSY under
the 60 s catalog refresh default.

## Change (`9099380f3`)

- **Server** (`query_directory_binding`, `query_auth_dir`):
  - Returns `EFS_ERR_NODATA` where it proves the published catalog older than
    the live namespace for the query root or an ancestor:
    - the directory exists live but is absent from the catalog;
    - its catalog name binding is missing live, or now names another
      inode/generation;
    - its live generation or parent differs from the catalog.
  - Live-transaction, catalog-read, deadline and admission refusals stay BUSY.
- **Client:** the existing mapping turns NODATA into ENODATA. The query RPC
  returns non-BUSY statuses at once, so the 16 client retries and 8 command
  retries that BUSY caused no longer happen.
- **`.efs` commands** (`command.py`, embedded `source.h`): ENODATA prints
  "efs command: not indexed yet: this directory was created, renamed or moved
  after the published catalog snapshot; retry after the next background
  refresh." and exits **75** (`EX_TEMPFAIL`). Other errors are unchanged
  (exit 1).
- **Tests:**
  - `posix_suite.py` `virt_stats_readable` and `virt_find_query` wait out
    exit 75 within the case budget (with a 2 s margin before the case alarm).
    They then report SKIP with that reason; any other command failure stays a
    hard FAIL.
  - `tests/live/efs_commands.py` `open_query` also tolerates ENODATA.
