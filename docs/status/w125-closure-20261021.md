### C1 rerun: chunk loss after eviction

`c1-20261021T1110` ran on `6ffa9e785f57`, 11:46–12:49 UTC.

- **Node A:** 4 mismatches and 31 EIO. The EIO are 0a, publish-stalled
  on chunks 1, 7 and 11.
- **Node B:** 1 mismatch.
- **Cross-check:** clean.

**Private repro:** `scripts/w125_modify_repro.sh` on node9901 runs the
same workload for 10 min. It found 44 mismatches with 0 errors, and 30
files were still bad at the final verify.

**Every bad file is large and was never packed.** Each has one or more
128 KiB chunks that read as zeros except for the bytes of one small
in-place overwrite (`scripts/w125_modify_inspect.py`). The chunk row is
a folded base with no spans.

**Cause:** a pre-existing client defect, not packing.

1. A chunk first written whole leaves its dcache slot with base
   `UNCOND`. The slot keeps it after the body is published and dropped.
2. A later small overwrite finds no local chunk row, because the staging
   evictor dropped the map. `dcache_load_and_patch` then skips the fetch
   and loads zeros plus the range, with `have_base=0`.
3. `dcache_apply_init` kept `UNCOND`. So the flush skipped the merge-base
   pull and published zeros plus the range as the whole chunk.

**Reduced repro:** `scripts/w125_evict_rmw.py` with
`EFS_CLIENT_META_MB=16`, 2,000 files of 256 KiB – 2 MiB and one overwrite
each:

- 1,144 files were bad, even with one thread;
- with 300 files (under the cap), or at the default cap, 0 were bad;
- `5c41111d1` fails the same way.

**Fix:** `4058d8141`. A partial init without a base resets the slot base
to 0, so the flush pulls the row and merges. `tests/test_partial_uncond.py`
fails on the old source and passes on the fix.

| Run on `4058d81416a0` | Result |
| --- | --- |
| `w125_evict_rmw.py`, 16 MB cap, 2,000 files, 8 threads, 3 rounds | 0 bad in every round |
| `w125_modify_repro.sh`, 600 s | 122,307 modifications, `mismatch=0 errors=0`, final `verified_bad=0` |

### C4/C5: space accounting and unattended compaction

`scripts/w125_space_compact.sh` first wrote 60,000 files of 1 B – 16 KiB
and let them pack, then deleted 50%. C5 followed:

- churn: 3 rounds of 30,000 writes and 50% deletes;
- then idle, with no `pack-compact`.

**First run** (`5c41111d1`): FAIL. After 15 min idle, 2,887 holed
segments were left; idle compaction built only 8 segments per minute.

Fixed in `e12e23394`:

- after 60 s idle, each batch compacts up to 256 segments
  (`EFS_PACK_COMPACT_IDLE_SEGS`);
- each batch is capped at 10 s (`EFS_PACK_COMPACT_IDLE_MS`);
- `tests/test_pack_compact_schedule.py` covers the change.

**Rerun** (`6ffa9e785f57`): PASS.
