## Scope

Task AA repairs the remote benchmark that [Task U](k32-write-cost-profile-20261028.md)
could not use as a direct write baseline. Raw fragment `--store` and synthetic
read paths are removed. Published `--size`, optional `--time`, `--read`,
`--workers`, `--id` and request-size control use normal client discovery,
committed membership, export setup, mount token/session, dcache and metadata
batching. Writes check the ticketed `efs_client_write`, synchronous per-inode
REPORT, final flush/REPORT and session shutdown. `--meta --size` uses the same
initialization and checked per-file publication; it no longer ignores failures.
No format, placement, durability default or new product behavior switch changes.

The namespace is one sequential file per worker under
`/bench-data-ID-wWORKER/payload`; existing fixtures are refused and writes retain
their files for independent readers. The documented `--size` is aggregate bytes
for data mode and per-file bytes for metadata mode. Full and final short requests
are counted exactly. Reads require the original identity and worker count,
check expected EOF when size is given and compare every returned byte to `A`.
Timed reads qualify only the bytes read. Timing includes initialization,
publication and checked shutdown. This is the synchronous library API, not the
FUSE write-acceptance callback pipeline.

The profile generator and Valgrind workload stop invoking deleted modes. The
latter retains workload logs and counts workload errors as failures, rather than
using an ignored command as data-path coverage. Its full detector gate is not
claimed by a normal code gate. Developer usage: [benchmarks](../using/benchmarks.md).
