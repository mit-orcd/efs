## What changed

Remote `--size` writes and `--read` now use normal client discovery, committed
membership, export setup, session, dcache, metadata batching and membership
refresh. Each worker owns one directory and sequential file. Every write,
synchronous per-inode REPORT, final flush/REPORT and shutdown is checked; the
refresh thread is joined before teardown. Metadata-mode payloads use the same
initialization and checked publication. No server, core write/read algorithm,
format, placement or durability-default change is involved.

Raw `--store` and synthetic fragment GET/window modes are deleted. The separate
`--time`-only network ceiling remains ACK-and-discard, never storage throughput.
The profile driver uses published fixtures and `--fixture-id`; the Valgrind
workload uses actual published writes/reads, retains its logs and counts workload
errors instead of ignoring them. The full Valgrind detector campaign is not
claimed by this ordinary code gate. See [developer usage](../using/benchmarks.md).

merge retains current devel's metadata fault object overrides. It supplies the
real stalled-compactor case, explicit developer graph gate and test corrections;

## Matched Task U comparison

checked teardown: **54 measured payload files, 12 GiB written and read back**.
Each row uses a fresh private three-member cluster, 1 GiB aggregate, 1/4/16 MiB
