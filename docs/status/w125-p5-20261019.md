# W125 P5 — modifying packed files — 2026-10-19

**Verdict: the modification matrix PASS on a private cluster: every case
reads back correctly right after the change, after repacking and after a
remount. Hole punch is refused for every efs file (EOPNOTSUPP), packed or
not. A new client now refuses to mount a cluster whose daemons do not
accept its protocol.**

Plan: [W125 implementation plan](../backlog/small-file-packing-plan.md),
phase P5. Design: [W125](../backlog/small-file-packing-default.md).

## What changed

- **Truncate:** a packed tail is kept like a span chain (no alias stub):
  the new size and the epoch fence hide bytes past EOF, also after a later
  extension; truncating to zero deletes the row and releases the record. A
  tail the client republishes replaces the packed row and releases its
  record (existing apply path).
- **Repack after modification:** a span publication over a packed base, and
  any truncate tail of chunk zero, record a packing candidate. The packer
  accepts a packed base with spans, reads the base record back from its
  segment, overlays the spans and switches the file into a new segment;
  the old record is released and the span fragments become GC records.
- **Fast failure:** efs-fuse declares its protocol to every discovered node
  before mounting and refuses to mount unless at least one node accepts and
  none refuses (3 s per node). Backward compatibility is not a goal: older
  clients simply fail against new daemons.

## Matrix

`scripts/w125_p5_matrix.sh REL` on node9901 (ports 17681–17683, packer
minimum age 2 s): 10 cases × 200 files of 1–12 KiB
(`scripts/w125_p5_modify.py`), packed, modified, verified at once, given
90 s to repack, then verified again after a remount.

| Case | Modification | Result |
| --- | --- | --- |
| keep | none | PASS, stays packed |
| overwrite | rewrite whole file (700 B–3.7 KB) | PASS, repacked |
| pwrite | 300 B written mid-file | PASS (span over packed base), repacked |
| append | 500 B appended | PASS, repacked |
| shrink | truncate to half | PASS, repacked |
| zero | truncate to 0, write 200 B | PASS, repacked |
| extend | truncate up by 4 KiB | PASS (zeros), stays packed |
| punch | `FALLOC_FL_PUNCH_HOLE` | EOPNOTSUPP, bytes unchanged (as for any efs file) |
| grow | append 20,000 B (past 16 KiB) | PASS, per-file fragments |
| shrink_extend | truncate to half, then back up | PASS (zeros in the gap), repacked |

Per-file fragments on n1: 0 after packing; 1,161 right after the
modifications; 200 after repacking (exactly the grown files).

**Mount refusal:** the new client against base-build daemons (`c903a80cd`)
exits after 9 s, `Cluster does not support client protocol 2: upgrade the
daemons before this client`, nothing mounted.

## Limitations

- Packed files that are only extended (no data written) stay packed with a
  smaller record than the file; reads zero-fill, which is correct.
- Concurrent readers during a modification and crashes mid-modification
  are not exercised yet (P7 crash injection).
