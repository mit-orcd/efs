## Failures and limits

* Valgrind `test_kv_lsm`: 3-byte definite leak, allocation stack
  `kv_buf_set -> kv_seg_install -> lookup -> lsm_get -> get_is -> apply_peer`.
  `test_query_delta` loses 128 bytes through the same KV read-buffer path
  in `worker_fixture` (exit 99). Daemon phases report 5,160 bytes definitely
  lost over TCP and 1,032 bytes over RDMA. FUSE-client TCP and RDMA phases
  report zero definite/indirect leaks.
  Source uses `static __thread struct kv_buf t_get_buf` without thread-exit
  cleanup; this is a likely buffer-lifetime defect, not cleared by the RDMA
  instrumentation rerun. `test_kv_lsm_concurrent` exits 142 (its alarm).
  `test_meta_apply` also reaches its external 300-second deadline (exit 124).
  All three pass natively; instrumented completion remains an open gate.


* Native tests `test_readindex_pair.py`, `test_raft_ack_window.py` and
  `test_host_outbox.py`: LeakSanitizer exits fatally on this host. A trivial
  malloc/free ASan program reproduces the same failure. All three pass with
  `ASAN_OPTIONS=detect_leaks=0`; leak coverage remains unavailable.
* `docs/check-architecture.py`: generated Markdown/HTML stale on deployed
  source; all internal links resolve. Already corrected by documentation-only
  `c1c1bc570`; current checkout passes all five checks.
* Private GC's first full run checks a newly mounted peer's verbs descriptors
  immediately and finds none (`gc_reclamation.py:2985`, proof at line 483).
  Unchanged repeat passes the full suite. Keep the startup race visible rather
  than replacing the first failure with the rerun verdict.
* Dedicated command/options gate: both test programs pass, then wrapper line
  740 rejects `efs-options-gates-<timestamp>` because it expects the exact name
  `efs-options-gates`. This is a cleanup-harness mismatch; the aggregate gate
  is FAIL and its later physical cleanup assertions are not reached.
* Initial fault invocation had 18 passes plus unbuilt simulator NOTRUN.
  Building `tests/faults/fault_sim` and rerunning on a new owned fixture gives
  24 passes. Expected fsync EIO after a private crash is a W71 fail-closed
  assertion, not repaired redundancy or automatic recovery.
* Initial GC launch lacked parent directories; corrected before the actual
  full runs. Initial cross-host launcher lacked client-to-client SSH agent
  access; rerun is driven through the login host. Neither setup failure is a
  passing qualification result.
