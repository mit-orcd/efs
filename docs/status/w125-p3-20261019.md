# W125 P3 — client read path and protocol handshake — 2026-10-19

**Verdict: packed files read back byte for byte PASS; handshake PASS for
old clients on new daemons; new clients on old daemons are refused but
operations hang until their deadline instead of failing fast (limitation).**
- **Read-back:** 3,000 files of 1 B to 16 KiB written, packed (200
  segments, 0 per-file fragments left) and verified byte for byte, again
  after a fresh remount; 1,000 more in the compatibility run.
- **Old client (base build) on new daemons:** every GETCHUNKS on its
  undeclared connections is refused and logged
  (`handler: refused message 69 … closing`); reading a packed file fails
  with EIO; writing a new file still works (the write path is unchanged).
- **New client on old daemons:** the client logs `node N refused or did not
  answer the protocol 2 declaration … incompatible server` and never uses
  the server; the mount succeeds but `ls` hangs until its 60 s timeout.
  That happens only in an uncoordinated upgrade.

Plan: [W125 implementation plan](../backlog/small-file-packing-plan.md),
phase P3. Design: [W125](../backlog/small-file-packing-default.md).

## What changed

- **Wire:** GETCHUNKS records gain `packed_ref` (96 B, after `deltas[]`, so
  the variable-length REPORT encoding never carries it) and the flag
  `EFS_CHUNK_REC_F_PACKED` (16; 8 stays never-reuse). The server fills it
  for packed rows instead of refusing them; nodes/checksums are the
  segment's placement.
- **Client:** the chunk table stores the packed reference
  (`efs_export_set_chunk_packed`, part of the read-cache identity). A
  packed base is read with GET_SEGMENT (any two fragments, each hashed),
  decoded and checked against the reference by `efs_packed_read_base_scratch`
  (restored `packed_reader`), zero-filled past the record; spans are
  overlaid as before. A malformed reference rejects the whole GETCHUNKS
  reply.
- **Handshake:** `EFS_MSG_CLIENT_HELLO` (165/166) declares protocol 2.
  efs-fuse and the daemons' pooled peer connections declare on connect;
  efs-mgmt `raft-getchunks` declares. The server answers GETCHUNKS,
  GET_SEGMENT and PUT_SEGMENT only on declared connections and closes an
  undeclared one. PUT, REPORT and publications are not gated: the write
  path is unchanged and per-file small files are still valid input. This is
  narrower than "no data read or mutation before declaration" in the plan's
  gap 8, recorded there.

## Reproduce

```sh
scripts/w125_p3_compat.sh NEW_REL OLD_REL
```

It runs the three cases above; `scripts/w125_p3_readback.py write|verify
DIR N` is the content check. In case 3, stop the hung mount with
`fusermount3 -uz` if `client.sh stop` blocks.

## Limitations and next

- New clients against old daemons should fail fast: mark an incompatible
  server so FUSE operations return EIO at once.
- Reads of packed files with spans on top (writes after packing) are
  covered by the overlay path but not tested yet (P5).
- Read amplification (one segment fragment per small file read) is not
  measured yet (P7).
