POSIX test catalog for agent review
====================================

Sources (authoritative; this file is a description, not the tests):
  tests/posix/posix_suite.py     191 single-mount tests
  tests/posix/posix_2client.py    63 two-client (peer) tests
  tests/posix/compare.py          classifies XFS vs efs TSV results

Four layers (this suite is 1–3 only)
------------------------------------
  1. POSIX syscall semantics     — posix_suite.py (local)
  2. Cache / coherency           — posix_2client sequential A-then-B
  3. Concurrent / race           — posix_2client ("ab", (fn_a, fn_b)) + local threads
  4. Failure / recovery / EC     — NOT in this suite (needs kill/inject harness)

Contract tags (XFS PASS is not always required):
  POSIX-required    Linux-VFS-required    Linux/XFS-behavior
  EFS-extension     intentionally-unsupported

Example: o_append_pwrite_absolute is Linux/XFS-behavior, not POSIX-required.

How to read this file
---------------------
Each entry is: test_id — what it does — PASS condition.

Harness (posix_suite.py):
  • One FUSE (or XFS) mount. Each test gets a fresh empty directory.
  • Fail(msg) = FAIL. Fail(msg, soft=True) = SKIP (feature absent).
  • Root (euid 0) no-ops many perm_* tests (Linux root bypasses mode bits).
  • efs data chunk is 128 KiB. Several tests straddle that boundary on purpose.
  • Optional ops (fallocate, xattr, copy_file_range) may return without
    failing if the FS returns EOPNOTSUPP. SEEK_HOLE/DATA soft-SKIPs.
  • Virtual .stats / .find are efs FUSE extras; absent → SKIP.

compare.py:
  • EFS-BUG = baseline (XFS) PASS and target (efs) not PASS.
  • TARGET-++ = XFS not PASS, efs PASS (known XFS quirks).
  • BOTH-FAIL = same failure on both (not counted as an efs bug).
  • Re-run XFS baseline after adding tests or only_t names are ignored.

posix2 harness:
  • Client A mutates, client B checks, no remount between steps unless the
    harness remounts B (prepare / missing parent).
  • Each test returns a list of ("a"|"b", fn) steps run in order, or
    ("ab", (fn_a, fn_b)) for simultaneous A∥B (layer 3).

Not covered (commented in posix_suite.py, needs a second mount in-harness):
  two FUSE clients in the single-mount suite — use posix_2client.py instead.
