1. atime nanoseconds dropped by the staged table (119 mismatches)
   `struct efs_inode_mem` had no atime_nsec / ctime_nsec; inode_copy_attr and
   inode_to_rpc_p dropped them, efs_export_set_atime took seconds only. A stat
   served from the local row (after the rename, `ll_lookup` of the final name)
   returned atime with nsec 0 while the server had 1780070101.301824970.
   Baseline on the old client (fcstor008, atime_repro.py): after-close OK,
   after-rename a=1780070101.000000000 WRONG. Fixed: fields added in the
   struct's padding (sizeof unchanged, 192 B), copied in both directions,
   efs_export_set_atime(…, atime, atime_nsec), local ctime bumps zero ctime_nsec.
   Gate: atime_repro.py 10/10 OK on fcstor007 (new), server truth matches.

2. mtime = close time (29 mismatches in ecopy; 1–2 per 5760 in the burst)
   Three distinct ways a chunk publish reached the server after the SETATTR,
   all under "utimens thought nothing was pending":
   a. efs_wb_thread: a job waiting in wb_overlap_inflight() was in neither the
      queue nor busy_ino[]; efs_wb_ino_pending_locked() said clean. Fixed:
      busy_ino[] is set at the pop (busy_len 0 until the claim so
      wb_overlap_inflight skips the slot).
   b. PUT window: every flusher marks the dcache entry clean BEFORE its PUT and
      marks the chunk dirty (put-record) AFTER. In between the chunk is in no
      set a REPORT snapshot or efs_dcache_flush_ino reads. Fixed: put_win_open /
      put_win_close per inode around the window (dcache_steal_dirty →
      flush_pipe_drain/add; dcache_flush_slot_inner); efs_dcache_flush_ino waits
      for the inode's windows (8 s bound → BUSY) and re-passes.
   c. The predicate itself (the one the burst kept hitting after a and b):
      efs_client_ino_is_dirty() is the dirty SET, not "has unpublished data". A
      threshold REPORT (only_ino=0) snapshots the ino mark that dcache_note_size
      set and ships an irec-only record while the bytes are still a dirty dcache
      entry. Trace (EFS_DCACHE_TRACE=1, burst-3-traced.txt run, ino 1756394):
        utimens ino=1756394 flush rc=0          <- no report lines before it
        report-irec ino=1756394 size=1000 only=1756394 sync=1 rc=0   (setattr drain)
        utimens ino=1756394 setattr rc=0
        dcache ino=1756394 ci=0 snap-steal | dirty=1 ... r=[0,1000)  <- data still dirty
        dcache ino=1756394 ci=0 put-record ...
        report ino=1756394 ci=0 only=0 sync=0 rc=0                  <- published after
      Fixed: efs_utimens_flush_dirty also checks efs_dcache_ino_pinned(ino)
      (held exactly while dirty entries exist; the evictor keys on the same).
   Gate: size_gate.py, 48 threads × 120 files × 8 sizes (1000 … 300000 B),
   write → futimens(ns) → close → rename, stat from the same client and from
   fcstor008:
     wb fix only (burst-1):            2 mtime mismatches / 5760
     + put window (burst-2, 3 runs):   2, 1, 1
     + predicate (burst-4, 4 runs):    0, 0, 0, 0   (server truth 0, 0, 0, 0)

3. size rounded to the chunk end (1 mismatch: mpfr Makefile.in 32398 → 131072)
