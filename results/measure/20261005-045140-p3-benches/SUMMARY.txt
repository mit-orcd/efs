bench" and "Client bench", asked Oct 2). Host: efs1 of the dev Tart

## Interpretation

- Reading per the plan's key: cpu (2.8 GiB/s) >> put (0.2-0.3 GiB/s) =>
  latency-bound; put ~= write => the pipeline adds nothing over the
  per-fragment round trip ON THIS HOST, where the server disk costs
  10-100x a real NVMe (fsync 36 ms, 64 KiB write 1.2 ms). The dd level
  was not re-measured — the plan defines it as the number we have, and a
  dev-VM dd is not the fcstor baseline (1.3-1.5 GB/s there).
- efsd --bench data: the write path reaches ~82% of the single-disk fio
  ceiling at QD16 (680 vs 825 IOPS) and then holds flat-to-degrading
  with depth because the disk is already saturated (p99 seconds at
  QD256; diskutil 82-99% throughout). On one device the writer pool /
  store is NOT the serialization point. The 1->6 path curve is noise on
  a shared device — the multi-NVMe question needs the fcstor run.
- efsd --bench meta: on this host a metadata write costs one disk fsync
  (36 ms); the engine sits exactly on the fsync ceiling at QD1, and the
  batch32 line (x32) is the amortization lever the hot-path contract
  describes. Nothing between the engine and the fsync.
- The few write errors at QD256 (1-7 per round) are EFS_ERR_BUSY slot
  handoffs under multi-second disk stalls — recorded, not hidden.

## Tool notes (what landed)

  efsd --bench data|meta: fragment store + writer pool exactly as the
  PUT/GET handlers drive them (same export bind, first-write path hint,
  O_DIRECT, sidecar sum, read-verify), paths x QD 1/16/64/256 ladders,
  exact p50/p99 per round, fio ceilings in the same log, iostats
  disk-write cross-check, /proc/diskstats util per round, --perf for top
  symbols. Bench roots must be scratch; the bench export tree is removed
  between path counts and afterwards. Replaces the old pwrite loop.
  efs-fuse <nodes> <export> <mnt> --bench cpu|put|write [--bench-time s]
  [--bench-mib n] [--perf]: levels cpu (arith only), put
  (efs_client_put_fragments_parallel at QD 1/16/64/256), write
  (efs_fuse_create_at -> efs_fuse_write 1 MiB -> efs_fuse_fsync_ino ->
  efs_fuse_release_ino, N files in parallel, flush in the clock, files
  unlinked after). Production path only: per-chunk hashes, REPORT on
  fsync, non-zero payloads.
