## Interpretation (added after the run)

- bound=rss-2x fired at 4352 MiB / 27 s, but the healthy nodes' KV
  counters grew identically (node1 l0_bytes 4180->30316, node3
  3904->24200; mt_bytes ~4 MB everywhere; n_l0=0 on ALL nodes) — the
  2x-pre-run stop is a calibration artifact of a small VM, not
  stalled-merge growth.
- No stall-specific effect up to 4.35 GiB: lag_max=0, no apply-sleep,
  no backpressure, recovery instant (recovery_s=0). With these flush
  sizes n_l0 never left 0 — merges were never needed, so "compactor
  stalled" was indistinguishable from "compactor idle".
- Hook fix this run needed: the parked check only ran after a compactor
  wake, so an idle compactor never noticed the fault file; the
  EFS_FAULTS build now wakes the wait every 100 ms while armed
  (kv_compact.c, faults builds only).
- Known defect: the sampler's RSS column under-reads nodes 2/3
  (pid_of in the background sampler; the foreground bound loop read
  node3 fine). Next refinement: differential RSS bound (node3 vs
  max(leaders)) and a pre-stall phase that forces n_l0 > 0 so the
  stall actually bites.
